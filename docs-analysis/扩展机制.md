# 扩展机制.md — 真实存在的扩展能力分析

## 分析快照

- 分支：`preview`；HEAD：`7cef741c2`；工作区：clean（仅新增 `./docs-analysis/`）；子模块：无。
- 分析范围：源码中真实存在的扩展点（CE/EE 缝、TipTap 扩展、Hocuspocus 扩展、装饰器控制器、Django app/Celery、设计系统组件）。
- 未覆盖范围：私有 EE 仓库内扩展的实际内容。

## 证据分类

- **Evidence**：扩展点接口/注册/加载有源码证据（`路径:行号`）。
- **Inference**：由占位与命名推导的扩展意图。
- **Unknown**：EE 仓库填充内容不可见。

## 核心结论

[Evidence] Plane **没有面向最终用户的通用插件系统**（无运行时动态加载第三方插件、无插件市场、无公共插件 SDK）。它提供的是**面向“社区版(CE) / 企业版(EE)”内部扩展的固定接缝（seam）**：前端通过空 `extendedRoutes`、`Base*Store`、editor `ce/ee` 目录；编辑器与实时服务通过 TipTap 扩展与 Hocuspocus 扩展注册；后端通过 Django app + Celery + 视图聚合；UI 通过组件库子包导出。这些扩展点**可以添加新实现、入口会发现并注册、调用方依赖抽象**的程度参差，需逐个评估（见下）。

## 1. CE/EE 扩展缝（最重要的“扩展机制”）

### 1.1 前端路由扩展缝

- 接口：`mergeRoutes(coreRoutes, extendedRoutes)`（`apps/web/app/routes/helper.ts:15`，按文件路径深合并）。
- 注册：`apps/web/app/routes.ts:17` 调用 `mergeRoutes`；`extendedRoutes` 来自 `apps/web/app/routes/extended.tsx`。
- 加载时机：构建期（RR7 路由配置）。
- 现状：**[Evidence] `extendedRoutes` 为空数组**（`apps/web/app/routes/extended.tsx`，已 first-hand 确认）。
- 稳定性：CE 占位，EE 仓库填充。**[Unknown]** EE 实际注入内容。
- 是否满足扩展判定：✅ 可添加新实现 ✅ 入口会合并 ⚠️ 调用方依赖具体路由（非抽象接口） ⚠️ 仅 web 有（space/admin 未见）。

### 1.2 前端 Store 扩展缝

- 接口：`Base*Store` 命名（`BaseWorkspaceRootStore`、`BaseAnalyticsStore`、`BasePowerKStore`…）。
- 注册：`CoreRootStore` 组装（`apps/web/core/store/root.store.ts:75`）。
- 现状：CE 提供 Base 实现；EE 覆写（[Inference] 经 `@plane/shared-state` 或 EE 包）。
- 判定：✅ 可覆写 ⚠️ 抽象程度有限（命名约定而非接口契约）。

### 1.3 编辑器 CE/EE 缝

- 目录：`packages/editor/src/ce/`（CE 真实扩展点：`ADDITIONAL_EXTENSIONS = []`、`TAdditionalEditorAsset = never`）与 `packages/editor/src/ee/`。
- **[Evidence] `ee/extensions/index.ts` 仅 `export * from "src/ce/extensions"`**（已 first-hand 确认）——EE 在本仓库为占位 re-export。
- 判定：✅ 有接口（`ADDITIONAL_EXTENSIONS`） ✅ 入口会聚合 ⚠️ 无实际示例（CE 为空数组）。

## 2. TipTap 编辑器扩展注册

- 接口：TipTap `Extension`（`@tiptap/core`）。
- 注册：`CoreEditorExtensions`（`packages/editor/src/core/extensions/extensions.ts:62`）聚合 ~20 自定义扩展（callout/table-suite/custom-image/work-item-embed/mentions/code-block/slash-commands/unique-id…）；另有 `CORE_EXTENSIONS`/`ADDITIONAL_EXTENSIONS`（`packages/editor/src/index.ts:8-26`）。
- 加载时机：编辑器实例化时（`use-collaborative-editor.ts`）。
- 权限边界：扩展运行在浏览器编辑器内，可访问 DOM 与 Yjs 文档。
- 判定：✅ 可添加新扩展 ✅ 入口聚合 ✅ 有大量实际实现。这是**仓库内最成熟的扩展机制**。

## 3. Hocuspocus 扩展（实时服务）

- 接口：`@hocuspocus/server` 扩展 + `onAuthenticate`/`onStateless` 等 hook。
- 注册：`getExtensions()`（`apps/live/src/extensions/index.ts:13-19`）返回 `[Logger, Database, Redis, TitleSyncExtension, ForceCloseHandler]`；`Hocuspocus({extensions, onAuthenticate, onStateless, debounce:10000})`（`apps/live/src/hocuspocus.ts:45-51`）。
- 加载时机：live 启动（`server.ts:42-55`）。
- 生命周期：连接级 + 文档级（fetchDocument/storeDocument/onLoadDocument）。
- 权限边界：扩展在 live 服务端运行，可经 REST 访问 Plane API（cookie 转发）、Redis。
- 错误隔离：Hocuspocus 扩展抛错按其框架处理。
- 判定：✅ 可添加 ✅ 入口注册 ✅ 有实现。**注意**：`broadcastToDocument` 访问 Hocuspocus 私有 `this["pubKey"]`（`extensions/redis.ts:132`）——跨版本脆弱。

## 4. 控制器/路由装饰器（@plane/decorators）

- 接口：`Controller/Get/Post/Put/Patch/Delete/Middleware/WebSocket`（基于 `reflect-metadata`）。
- 注册：`registerController(router, Controller, deps=[])`（`packages/decorators/src/controller.ts:23-108`），按原型元数据识别 REST vs WS 并挂载。
- 消费者：**仅 `apps/live`**（`server.ts:92`）。
- 判定：✅ 可声明式加端点 ✅ 入口发现 ⚠️ 单一消费者（未推广到其他应用）。

## 5. 后端扩展（Django app + Celery + 视图聚合）

- 新增 Django app：写 `apps.py`（AppConfig）→ 加入 `INSTALLED_APPS`（`common.py:97-118`）→ 在 `plane/urls.py` 挂载。
- 新增 Celery 任务：`tasks.py`（autodiscover，`celery.py:116`）或显式 `CELERY_IMPORTS`（`common.py:338-351`）；beat 调度经 `beat_schedule` 或 `django_celery_beat` DB。
- 视图聚合：`plane/app/views/__init__.py`、`plane/api/views/__init__.py` 按域 re-export。
- 权限：可自定义 permission class 并挂到视图。
- 判定：✅ 标准 Django 扩展 ✅ 文档化程度低（无插件 SDK） ⚠️ 不是“插件系统”，是“源码级扩展”。

## 6. 配置扩展（运行时开关 / InstanceConfiguration）

- 环境变量 + `InstanceConfiguration`（加密 key/value，`plane/license/models/instance.py`）→ `get_configuration_value()`。
- 开关：`ENABLE_SIGNUP`、`ENABLE_EMAIL_PASSWORD`、`ENABLE_*_SYNC`、`ENABLE_READ_REPLICA`、`ENABLE_DRF_SPECTACULAR`、`USE_MINIO` 等。
- 判定：✅ 运行时可改 ⚠️ 属“配置项”而非“插件”。**不夸大为插件系统**。

## 7. UI 扩展（组件库）

- 新增组件：在 `@plane/propel`（推荐）或 `@plane/ui` 建目录 + 注册 `tsdown.config.ts` 入口 + 加 `package.json` exports + Storybook story。
- 主题：`@plane/tailwind-config/variables.css` token（`@theme`）。
- 判定：✅ 可加组件 ✅ Storybook 隔离开发 ⚠️ 面向内部开发者，非终端插件。

## 8. 数据源 / 平台 / 子模块 / Feature flag 扩展

- 数据源：仅 Postgres（+ 可选读副本）、S3/MinIO、Redis、RabbitMQ；无外部数据源插件接口。
- 平台：无桌面/移动原生扩展。
- 子模块：**无 Git 子模块**。
- Feature flag：环境变量与 `InstanceConfiguration`（见 §6）。
- 运行时动态加载：**无**（无动态 import 第三方插件、无 eval/load）。

## 9. 扩展生命周期 / 权限边界 / 兼容性 / 测试

- 生命周期：编辑器扩展随编辑器实例；Hocuspocus 扩展随 live 进程/连接；Django app/Celery 随进程；前端缝随构建。
- 权限边界：服务端扩展可访问 DB/Redis/API（受同进程权限）；浏览器扩展受同源 + cookie。
- 兼容性：无版本化插件契约；CE/EE 缝无稳定性承诺文档。
- 测试：`packages/ui`/`propel` 有 Storybook；编辑器扩展无单测；Hocuspocus 扩展无测试（仅 PDF 测试，见 `测试与CI.md`）。

## 已确认事实

- 无通用插件系统/市场/SDK；扩展以 CE/EE 缝 + 框架级扩展（TipTap/Hocuspocus/Django/Celery）为主。
- 最成熟的是 TipTap 编辑器扩展（~20 实现）与设计系统组件（Storybook）。
- CE/EE 缝（extendedRoutes/Base*Store/editor ee）在本仓库为空/占位，由私有 EE 仓库填充。

## 合理推断

- `Base*Store`/`extendedRoutes`/`ee/` 是为单体仓库在 CE 与 EE 间共享代码而设计的内部接缝，非面向第三方。

## Unknown 与待验证事项

- EE 仓库（plane-cloud/plane-ee）填充了哪些 `extendedRoutes`/`Base*Store`/`ee/`；是否存在未文档化的扩展 SDK。

## 批判性评估

- 把“CE/EE 缝”或“配置开关”当作“插件系统”是夸大——本仓库无运行时第三方扩展能力。
- 部分扩展点（Hocuspocus `broadcastToDocument` 私有 API 依赖、`Base*Store` 命名约定）稳定性不足，跨版本/跨实现易碎。

## 建设性改善建议

- [Recommendation] 若计划开放第三方扩展，先稳定一两个接缝（如 editor `ADDITIONAL_EXTENSIONS`、webhook）并补版本化契约 + 示例 + 测试；否则在文档明确“无插件系统，仅 CE/EE 内部缝”。优先级：低；难度：中。
- [Recommendation] 去除 Hocuspocus 私有 API 依赖（`this["pubKey"]`），改用官方广播接口或封装隔离。优先级：中；难度：中。
- [Recommendation] 为 `Base*Store` 引入显式接口/契约，降低 EE 覆写的隐式耦合。优先级：低；难度：中。
